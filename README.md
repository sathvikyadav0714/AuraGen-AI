## 🏛️ Architecture Overview (Member 4)

AuraGen Member 4 is responsible for securely transforming complex, high-friction financial interfaces into simplified, step-by-step conversational wizards **in real time without reloading the page or losing previously entered user data**.

```
[ Member 1: Friction Detection ] ──(Telemetry)──> [ Member 2: Backend WebSocket ]
                                                              │
                                                              ▼
[ Member 4: Dynamic UI Renderer ] <──(AI Schema)── [ Member 3: LLM UI Agent ]
       │
       ├──> ASTValidator.js (Strict JSON Schema & Prototype Pollution Guard)
       ├──> ComponentRegistry.js (13 Safe Pre-Built React UI Primitives)
       ├──> FormWizard.jsx (Step-by-Step Conversational Wizard)
       ├──> TransitionManager.jsx (Spring Physics & Cognitive Friction Badge)
       └──> FallbackUI.jsx (Data Preservation & Auto-Recovery Banner)
```

## 🔒 Security Architecture (AST & Allowlist Enforcement)

Direct client-side execution of raw LLM-generated code (`eval()`, `new Function()`) poses severe XSS and script injection vulnerabilities. Member 4 enforces a **zero-trust sandboxed schema rendering model**:

1. **Strict JSON Schema Format:** AI models output pure declarative JSON schemas rather than raw executable JavaScript.
2. **ASTValidator (`ASTValidator.js`):**
   - Verifies all step and component keys against strict allowlists (`ALLOWED_STEP_KEYS`, `ALLOWED_COMPONENT_KEYS`).
   - Deeply strips malicious payloads, inline handlers (`on*`), and dangerous protocols (`javascript:`, `vbscript:`, `data:text/html`).
   - Shields against Prototype Pollution (`__proto__`, `constructor`, `prototype`).
3. **Component Registry Allowlist (`ComponentRegistry.js`):**
   - Enforces an allowlist of 13 certified React functional components:
     - `TextInput`, `NumberInput`, `EmailInput`, `PhoneInput`, `SelectInput`, `TextArea`, `RadioGroup`, `CheckboxGroup`, `InfoBlock`, `ProgressBar`, `Heading`, `Paragraph`, `Divider`.
   - Unknown or unverified components are rejected and rendered safely in developer sandboxes.

## 🔄 Bidirectional Data Preservation

When a high cognitive load score triggers UI transformation:
1. Input values entered in the original form are cached in state (`preservedFormData`).
2. The values are automatically injected into corresponding fields inside the dynamic `FormWizard`.
3. If the user exits the wizard midway, all newly entered fields are seamlessly passed back to the parent form via `onStateChange` with **zero data loss**.

## 🎓 Viva & Technical Interview Notes

### Q1: Why use JSON Schema rendering instead of dynamic Babel AST compilation?
> **Answer:** Executing runtime JavaScript code generated by LLMs introduces arbitrary code execution (ACE) and Cross-Site Scripting (XSS) risks. By restricting the AI output to declarative JSON schemas verified against a pre-compiled React component allowlist, we achieve 100% type safety and zero executable injection risk.

### Q2: How does AuraGen prevent data loss during UI transformation?
> **Answer:** We decouple form state from UI component lifecycles. State is lifted to the parent page hub and synchronized bidirectionally through `onStateChange` callbacks. When the component tree dynamically morphs from `OriginalForm` to `FormWizard`, the state remains intact and binds into the wizard steps.

### Q3: How does the system handle network drops or invalid AI responses?
> **Answer:** If the AI model generates an invalid schema or network fails, `DynamicRenderer` catches the issue through an `ErrorBoundary` and renders `FallbackUI`. The user sees a Data Preservation Guarantee notice, detailed diagnostics, and can return to the original form or trigger an auto-recovery countdown.
